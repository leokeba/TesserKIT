## What to do first

Ranked by risk times reach. Each item links to its section.

1. **Use-after-free in a streamed read while a peer is evicted** (TesserAPI, confirmed with ASan). Any gateway reading `/` or `/peers` while peers come and go can hit it. [T-API 1](#t-api-1-use-after-free-when-a-streamed-read-yields-while-a-peer-node-is-evicted)
2. **UDP's duplicate filter drops valid messages, or runs them twice** (TesserAPI, confirmed). A gateway notifying many peers loses sets and replies silently; peer-table eviction runs a request twice. The fix is wire-compatible. [T-API 2, 3](#t-api-2-udps-duplicate-window-drops-valid-messages)
3. **Heap overflow in NowTP's `buildFrame`** when a peer's frame size shrinks while a message is queued (confirmed with ASan). [NowTP 1](#nowtp-1-heap-overflow-when-a-peers-frame-size-shrinks-while-a-message-is-queued)
4. **A LittleFS mount failure formats the partition and silently brings back NVS's stale settings,** accounts included (TesserKIT, reasoned, each step traced). This is the most likely explanation for board B coming up on its old network on 2026-10-21. [KIT 1](#kit-1-a-littlefs-mount-failure-silently-reverts-every-setting-to-nvss-old-copy)
5. **A stalled HTTP body holds the httpd task forever,** before authentication (TesserAPI, confirmed). A phone leaving Wi-Fi mid-POST is enough. [T-API 4](#t-api-4-a-stalled-http-request-body-holds-the-httpd-task-forever)
6. **TesserUI fetches peers' root schemas 2^N − 1 times** on a page of peer links (confirmed by simulation: 63 requests for 6 peers). Each one counts against a gateway's `maxPending` of 4. [UI 1](#ui-1-peer-root-schemas-are-fetched-an-exponential-number-of-times)
7. **Mqtt ignores a rename** (TesserKIT, confirmed with a host probe). Commands on the old topics are dropped and Home Assistant entities go stale until a restart. The fix is one line plus a test. [KIT 7](#kit-7-mqtt-ignores-a-hostname-change)
8. **Per-node metadata is about 20–22 KB of heap in `/sys`,** more than the nodes themselves. A slimmer layout in TesserAPI saves 9–15 KB at rest on every TesserKIT device. [RAM 1](#ram-1-per-node-metadata-about-2022-kb-in-sys)
9. **RemoteNode costs 864 B at rest.** Shared mutexes and parts allocated only when used save about 10 KB on a gateway with 16 peers. [RAM 2](#ram-2-remotenode-864-b-at-rest)
10. **Transient buffers that bypass the byte budget:**
    - the streamed-subscription snapshot (up to about 32 KB of peak, unguarded);
    - MQTT's 16 KB publish queue;
    - NowTp's and Peers' per-second list rebuilds.

    These are the abort paths Phase 1 set out to close. [RAM 3](#ram-3-transient-buffers-outside-the-byte-budget)
11. **TesserUI leaves subscriptions behind on timeouts, and never notices a dead WebSocket.** Both waste a small node's subscription slots, or leave the page showing frozen values marked "Live". [UI 2, 3](#ui-2-a-subscribe-that-times-out-leaves-subscriptions-on-the-node)
12. **Bluetooth's 56 KB of DRAM stays reserved when Bluetooth is off.** The controller reserves it at link time (`CONFIG_BTDM_RESERVE_DRAM`), and nothing calls `esp_bt_mem_release` when `/sys/bluetooth/enabled` is false at boot. Releasing it gives 56–65 KB of heap to a full-profile device with Bluetooth off; switching Bluetooth on then needs a restart. [Measurements](#measurements)
13. **Configuration-only flash savings, measured together at 87.7 KB** on the full image (20.8 KB of room locally):
    - ESP-IDF's common CA bundle: 42.6 KB.
    - Log level ERROR and no error names: about 26 KB.
    - TLS client only, fewer curves: 9.4 KB.
    - MQTT over WebSocket off: 5.2 KB.

    IPv6 off would save about 15 KB more, after a one-line TesserAPI guard. [Measurements](#measurements)
14. **Cheap flash in the code:**
    - NowTP Streams compiled out: 5.5 KB.
    - TesserUI's files and editor chunks only where used: up to 7 KB.
    - One sort instantiation in TesserKIT: about 4 KB.

    [Flash](#flash)

## Bugs

### TesserAPI

#### T-API 1. Use-after-free when a streamed read yields while a peer node is evicted

High, confirmed (ASan: `scratchpad/repro/evict.cpp`). `src/tesser/api.cpp:697-723` (`renderChildren` → `yieldPoint`), `src/tesser/datagram_peers.cpp:568` (`roomToMount` → `Object::remove`).

- **What happens:**
  - `yieldPoint()` releases the API lock between an object's children whenever the reply wants draining: HTTP replies over 512 B, WebSocket, serial and BLE.
  - Meanwhile the device task can mount a new peer. At `maxMounted` (16) it evicts an offline `RemoteNode` and deletes it.
  - The render loop then calls `c->next()` on the freed node.
- **Fix:** defer deletion. `Object::remove` unlinks the node and parks it; `Api::poll()` frees it once no handler is yielded (an atomic count of yielded handlers). The other option is to block eviction while any handler is yielded.

#### T-API 2. UDP's duplicate window drops valid messages

High, confirmed (`scratchpad/mesh/repro/repro2.cpp`). `src/tesser/udp_link.cpp:307`, `407-431`.

- **What happens:**
  - One sender-wide `nextId_` feeds every destination and every broadcast, but each receiver keeps a window of the 64 ids behind the newest it completed.
  - If 64 ids go elsewhere while a multi-fragment message to B waits for a retransmission, and a later message to B completes first, B acks M's fragments as already seen and never delivers them.
  - The sender believes the message was delivered, so nothing goes offline. The call times out after 3 s.
- **When it happens:** a gateway notifying 15 peers at 20 Hz uses 64 ids in about 200 ms.
- **Fix (wire-compatible; each side fixes its half against old nodes):**
  - Sender: a per-destination id counter for reliable unicasts.
  - Receiver: a separate window for datagrams flagged `kBroadcast`.
- **Spec:** update DESIGN §10.7.

#### T-API 3. UDP peer-table eviction runs a request twice and loses restart detection

Medium, confirmed (`mesh/repro/repro3.cpp`). `src/tesser/udp_link.cpp:378-403`, `582`.

- **What happens:**
  - Every datagram, adverts included, takes an LRU slot in `maxPeers` (16).
  - An evicted peer comes back with an empty window, so a retransmission whose first copy already ran runs again. This breaks §10.7's "runs once".
  - With 17 or more advertising hosts on a LAN, the table thrashes. Evicted peers are never reported Restarted or Silent, which `watchDevices` relies on.
- **Fix:**
  - Give advert-only and query-only hosts a light table.
  - Never evict a peer with messages in flight or the `advertised` flag.
  - On evicting an advertised peer, forget it (`Silent`).
  - Size the table from `maxMounted`.

#### T-API 4. A stalled HTTP request body holds the httpd task forever

Medium, confirmed. `src/tesser/transports/http_server.cpp:1119-1126`.

- **What happens:**
  - `if (n == HTTPD_SOCK_ERR_TIMEOUT) continue;` has no limit; `drain()` and `receiveFile()` stop after 4 timeouts.
  - A client that sends a `Content-Length` and stalls blocks the single httpd task: all HTTP, WebSocket, streams and async answers stop. This happens before authentication.
  - The body is also allocated with plain `new` (up to 4 KB), not reserved.
- **Fix:** bound the timeouts as `drain()` does, and reserve the body through `memoryBudget()`, answering `busy` without room.

#### T-API 5. Queued mode: a peer's first Subscribe frees its subscriber while the request is queued

High in apps that enable it (TesserKIT doesn't), confirmed (ASan: `mesh/repro/repro1.cpp`). `src/tesser/datagram.cpp:552-567`, `api.cpp:1543`, `1616-1640`.

- **What happens:** with `config().queued`, `handle()` deletes the PeerSubscriber because it has no subscription yet. `runQueued()` then subscribes the dangling pointer.
- **Fix:** clean up subscribers in `process()` only when they have neither subscriptions nor queued requests.

#### T-API 6. Dropped calls leak pending slots; teardown is unsafe for relays

Medium, confirmed (`mesh/repro/repro4.cpp`). `src/tesser/remote.cpp:105-110` (`cancelCalls`), `datagram_calls.cpp:524-533`, `datagram.cpp:66-72`, `remote_relay.cpp:204, 385-387, 403`.

- **What happens:**
  - Destroying a remote node or an endpoint drops `forward()`'s handler uncalled, so `pendingDone()` never runs. `api.pending()` stays at 1 forever: one of 4 slots gone, plus its detached reply.
  - `RemoteFile` keeps a raw `endpoint_`.
  - `cancelCalls` destroys handlers under the endpoint lock (rank 80); `~RemoteFile` then takes the API lock (rank 20) under it.
- **Fix:**
  - Move the slots out and destroy them outside the lock.
  - `forward()` captures an RAII guard that answers `internal` and calls `pendingDone()` when dropped.
  - `RemoteFile` holds a weak handle.
- **Spec:** DESIGN §14 says nodes and endpoints can be "destroyed in either order", which overstates what is safe.

#### T-API 7. `NowTpTransport::end()` forgets nothing

Medium, confirmed by reading. `src/tesser/transports/nowtp_transport.cpp:191-202`.

- **What happens:**
  - UDP's `end()` forgets every peer (`PeerLoss::Stopped`); NowTP's only unlistens.
  - NowTP routes stay "online", so remote nodes keep choosing them and don't fail over to UDP. Streamed sets go back to unsent every tick.
  - In task mode, calls in flight never expire (see T-API 6).
- **Impact:** TesserKIT switches NowTP off at runtime this way.
- **Fix:** forget every peer, then run one last `process()`.

#### T-API 8. A late deferred reply races the timeout answer on async HTTP

Medium-low, reasoned. `http_server.cpp:197-216` against `1334-1360`.

- **What happens:** once `deferTimeoutMs` passes, the esp_timer task writes `st->body`. A deferred reply arriving at the same moment clears and appends to the same string from another task, because nothing checks `answered`.
- **Fix:** make the deferred sink a no-op once `answered` is set.

#### T-API 9. Line transports write notifications under the API lock, blocking on BLE

Medium, confirmed by trace. `src/tesser/line_transport.cpp:17, 255`, `transports/ble_transport.cpp:317-347`.

- **What happens:**
  - `flush()` and `emitEvent()` reach `output_` directly.
  - BLE waits up to 2 s per piece when NimBLE's pool is full. UART blocks for about 180 ms per 2 KB at 115200 baud.
  - DESIGN §9 says BLE never waits under the lock.
- **Fix:** queue into `waiting_` and flush from the transport's own task.

#### T-API 10. Smaller TesserAPI bugs

All low.

- **OOM reported as malformed JSON** (confirmed): `DeserializationError::NoMemory` answers `bad_request` "malformed JSON" (`http_server.cpp:1138`, `envelope.cpp:65`, the line and envelope handlers), so clients don't retry. It should be `busy`/`low_memory`.
- **Migration can run twice after a partly failed save** (reasoned): `persistence.cpp:357-368`. If `saveRecords(true)` fails partway, some records are in the new shape but `@version` stays old, and the next boot migrates them again. Fix: a version per record, or migrations that recognise the new shape.
- **NowTP buffer sends report call id 0** (confirmed by reading): `nowtp_transport.cpp:121`. A refused relay part then waits out 3 × 3 s instead of failing at once (§10.3 says otherwise). Fix: compute `callIdOf()` before handing the buffer over.
- **`localPath_` race** (reasoned): `remote.cpp:357-364, 397-401` writes it without the API lock, and `remote_upstream.cpp:421` writes it under it. Fix: compute into a local and publish once.
- **Removing a remote node under the API lock can deadlock** (reasoned): `datagram_peers.cpp:264-275` waits for pins held by a task waiting for the API lock. Fix: document "remove outside the lock", or defer to `process()`.
- **`BleTransport::begin()` failures leave NimBLE initialised and `instance` set** (confirmed by reading). After that, neither `end()` nor `begin()` works, and the controller's memory stays allocated on exactly the short-heap boards where `xTaskCreate` fails. Fix: unwind on each failure.
- **`attach()` users: a reused socket fd inherits the previous WebSocket client** (reasoned): `http_server.cpp:650`. The new connection gets the old client's subscriptions and level. TesserKIT uses `begin()` and isn't affected. Fix: drop any `WsClient` for the fd at the handshake.
- **`EventNode` fills its cached `path_` on the first `emit` without synchronisation** (reasoned): two tasks emitting first race on it.

### NowTP

#### NowTP 1. Heap overflow when a peer's frame size shrinks while a message is queued

High (memory corruption, low likelihood), confirmed (ASan: `repro/shrink.cpp`). `src/nowtp/engine.cpp:313-336`.

- **What happens:**
  - `queue()` fixes `fragSize` from the frame size at queue time. `buildFrame()` grows `frame_` only to the destination's current size, then copies the old chunk size.
  - A peer reported Lost, or re-announced smaller, reverts to 250 B. A queued 1470-byte frame then writes 1200 B past `frame_` while `frame_` has never grown.
  - Once `frame_` is 1470 B, the overflow can't happen, but frames of the old size still go to a v1 peer, which drops them.
- **Fix:** size the copy from the message itself (`kFragmentHeaderSize + fragSize`), or build headers in place (see [RAM 4](#ram-4-nowtp)), which removes the buffer altogether. Add a host test.

#### NowTP 2. Security stops answering challenges if it starts after 24.8 days of uptime

Medium, confirmed (`repro/window.cpp`). `src/nowtp/security.h:207`, `security.cpp:399-404`.

- **What happens:** `responseWindowStart_ = 0`, so at a clock ≥ 2^31 ms, `int32(now - 0)` is negative and the window never resets. After 20 responses the node answers no challenge until the clock wraps, and peers drop its authenticated traffic.
- **Trigger:** any `begin()` after 24.8 days, such as TesserKIT restarting NowTp on a settings change.
- **Fix:** start the window in `start()`.
- **Test:** add a `NOWTP_CLOCK_START` knob and run the suite near 2^31 and 2^32. Run from there, only two tests fail, both on absolute-time assumptions.

#### NowTP 3. Unauthenticated challenges force a reseal of everything queued to the claimed MAC

Medium. The path is traced; the delivered-but-Timeout outcome is reasoned. `security.cpp:397-431`, `engine.cpp:646-658`.

- **What happens:**
  - **CPU:** anyone can send challenges from any MAC. Each one re-HMACs every queued message to that MAC: up to 24 KB, about 15 ms with the lock held, 20 times a second.
  - **Wrong outcome:** after two reseals within one message's life, the receiver's bound ack matches neither bind. The sender ends the message `Timeout` although it was delivered, so TesserAPI may resend a non-idempotent set.
  - **Shared limit:** the 20/s response limit is global, so one sender can use up everyone's responses.
- **Fix:**
  - Reseal at most once per challenger per second.
  - Keep each seal's bind.
  - Rate-limit responses per challenger.

#### NowTP 4. Smaller NowTP bugs

- **A message stalls on its own spent credit** (low-medium, confirmed: `repro/credit.cpp`):
  - **Where:** `engine.cpp:409, 489-495`.
  - **What happens:** when frame 0 of a multi-frame message fails at the MAC, the retry waits about 300 ms instead of 4 ms.
  - **Fix:** spend the credit only when the frame is delivered.
- **Polled mode: `pair()` runs the engine from the caller's task** (low-medium, reasoned):
  - **Where:** `espnow_transport.cpp:358-367`; TesserKIT `platform/esp/nowtp_esp.cpp:219-237`.
  - **What happens:** TesserKIT pairs in its own `tk_pair` task. While that task waits, it processes frames itself, so TesserAPI's receive handlers and time sync run concurrently with the device task. This breaks TesserKIT's assumption that NowTP runs in the device task.
  - **Fix:** in `Host::sleep`, process events only from the poller's task; otherwise wake the poller and delay.
- **`addPeer(mac, 0)` reverts a discovered v2 peer to 250-byte frames** (low, confirmed by reading):
  - **Where:** `espnow_transport.cpp:820`.
  - **Fix:** with size 0, recompute from the peer's PeerInfo.
- **Allocations on the receive path** (low, confirmed by reading). AGENTS.md says the receive path never allocates, but the transport does in five places:
  - `linkHealth_.push_back` for every new MAC, foreign ESP-NOW traffic included (`espnow_transport.cpp:1450`);
  - `sizes_` on Found events (`:340`);
  - `linkChecks_` (`:1492`);
  - the unbounded `fallback_.tried` (`:1676`);
  - a 12-byte capture that allocates on every link check (`:1768`).

  **Fix:** reserve these vectors in `begin()` and bound `tried`.

### TesserKIT

#### KIT 1. A LittleFS mount failure silently reverts every setting to NVS's old copy

Medium, reasoned (each step traced). `src/tesserkit/platform/esp/filesystem_esp.cpp:32`, `settings_store.cpp:135-144`, TesserAPI `src/tesser/storage.cpp:27-29`.

- **What happens:**
  - The mount sets `format_if_mount_failed = true`. esp_littlefs formats on any `lfs_mount` error (`LFS_ERR_NOMEM` included) and only logs a warning, before the Log service captures anything.
  - `moveSettings()` then finds no `@moved`, erases the directory and imports NVS's copy. That copy dates from the original move: NVS is kept but never written again.
  - The device comes up with weeks-old settings: old networks, a different auth key, possibly no admin account, which makes it open.
  - A second path: `FileStorage::load()` returns false on any `fopen` failure, so a failed read of `@moved` also wipes and re-imports.
- **Other triggers:** a power cut corrupting the superblock; a rollback across a LittleFS minor-version bump.
- **Likely link:** this matches board B's unexplained loss on 2026-10-21 ("as if it read NVS's copy from before its settings moved").
- **Fix:**
  - Format only a blank or foreign partition (no LittleFS superblock). Otherwise keep the settings in NVS for that boot and say so in `/sys/status/settings`.
  - Write a "moved" marker into NVS at move time. If the filesystem lacks `@moved` but NVS has it, report "settings restored from an older copy" as an error.
  - Treat only ENOENT as "not moved".
  - Fix the comments in `platform.h:356` and `settings_store.h:86-93`, which describe the opposite.

#### KIT 2. Secure mode: the access point comes up open at boot, then restarts

Low-medium, confirmed by tracing the examples' order. `network.cpp:534, 538-549`, `auth.cpp:219-220`.

- **What happens:**
  - Network starts before Auth. `updateAp()` raises the AP in `start()` (mode Always, or no network saved), while `dev_.secure()` is still false, so the AP is open.
  - Auth then sets secure mode, and about 150 ms later the AP restarts with WPA2.
  - UdpApi's `peerAccess` "auto" reads `secure()` too early in the same way.
- **Fix:** a phase after `api_.load()` and before any `start()` (e.g. `Service::loaded()`) in which Auth sets `dev_.secure(!open())`.

#### KIT 3. Auth rewrites the whole `/sys` record at every boot

Low-medium (flash wear), confirmed. `auth.cpp:203, 216-218, 284-285, 302-306`.

- **What happens:** `boots_++; bootsNode_->changed();` runs on every boot, and a record is a whole top-level node: up to 6.7 KB in NVS. A Sleep device waking every few minutes rewrites it hundreds of times a day. The counter only binds clockless tokens to one boot.
- **Fix:** a random 32-bit boot id drawn at boot, not persisted, inside the signed token.

#### KIT 4. A migration rewrites settings before the new image is confirmed

Low, reasoned. `device.cpp:236-259, 318-323`, `firmware.cpp:554-564`.

- **What happens:**
  - After an update that raises a settings version, every record is saved again in sparse form within seconds, before the 60 s confirmation.
  - On a rollback, the old firmware reads migrated records. A value the user set equal to the new default was dropped, so the old default applies.
  - The application's `migrate()` can also be called with a version newer than its own (`app != appVersion_`). This is undocumented.
- **Fix:**
  - Store a `before-update` backup when Files exists.
  - Skip or document migrations from a newer version.
  - Optionally hold the rewrite while `Firmware::pending()`.

#### KIT 5. A restart can lose unsaved changes, and can lock out the only admin

Low, reasoned. `auth.cpp:83-122, 249-254`, `device.cpp:423-427`.

- **What happens:**
  - While a new account's hash is computing, its stored password is "". `open()` counts any admin, so a restart inside that window (0.3–2 s) leaves a closed device whose only admin can't sign in.
  - More generally, `restartIn` doesn't wait for `settingsWaiting()`.
- **Fix:**
  - `open()` ignores admins without a hash.
  - The restart waits, bounded at 2–3 s, for pending Auth jobs and waiting saves.

#### KIT 6. Any successful save clears `waiting_`

Low; the logic is confirmed. `settings_store.cpp:90, 101-106`, `backup.cpp:78-79`.

- **What happens:**
  - One string holds the waiting reason, so any record that saves clears it, even while `sys` still waits.
  - A restore can then answer "the settings couldn't be saved" although TesserAPI retries, and `/sys/status/settings` flickers.
- **Fix:** keep the reason per key.

#### KIT 7. Mqtt ignores a hostname change

Medium-high, confirmed (host probe: `scratchpad/probe/probe.cpp`). `src/tesserkit/mqtt.cpp:220-225`.

- **What happens:**
  - `settingsGen()` sums only Mqtt's own nodes. With the default prefix (`tesser/<hostname>`) and clientId, a rename through `/sys/name` doesn't restart the session.
  - The will and the 8 `/set` subscriptions keep the old prefix, but `command()` compares against the new one, so commands are dropped.
  - Home Assistant configs still point at the old state topics.
- **Fix:** add `dev_.hostnameGeneration()` to the sum when `prefix_` or `clientId_` is empty; `discover()` already clears configs whose topic changed. Add the probe as a host test.
- **Related:** the open item on HA `unique_id` duplicating entities after a rename.

#### KIT 8. High-rate writers to persisted nodes rewrite settings every 2 s

Medium (flash wear), reasoned. `dmx.cpp:296-319`, `sequencer.cpp:270`, `mqtt.cpp:463`, `examples/idf/full/main/main.cpp:84-88, 233-263`.

- **What happens:**
  - DMX mappings (up to 44 writes a second), Sequencer steps and MQTT commands write through `LocalClient`. On a `persist()`ed target, TesserAPI's 2 s debounce rewrites the record every 2 s for as long as the input runs: about 43,000 saves a day.
  - The full example does exactly this: the blink and the Art-Net mappings target the persisted `/led/on` and `/led/brightness`.
- **Fix:** a "don't persist this change" write option in TesserAPI (gap report). Meanwhile, make the example's targets non-persisted.

#### KIT 9. Sequencer timed steps drift by up to a period each

Medium-low, confirmed (probe: 10 × 50 ms took 580 ms). `sequencer.cpp:254, 264`.

- **What happens:** `startedMs_ = nowMs` takes the tick that noticed the end of the previous step, not its deadline, so the error accumulates over a show.
- **Fix:** chain from the previous step's deadline, clamped if more than a period late.

#### KIT 10. PwmOutput's `restartAt()` can report a restart that never happens

Low-medium, reasoned. `platform/esp/pwm_esp.cpp:188-206`.

- **What happens:**
  - The 200 µs lead is checked inside the critical section, but the alarm is armed after it, and `pending_` is set after that.
  - If the device task is preempted past the lead, the alarm lands behind the counter and waits for the wrap, while the call returns true.
- **Fix:**
  - Set `pending_` before arming, then re-read the counter after arming, as `pulses_esp.cpp`'s `step()` does.
  - Consider core 1 at level 3, as Pulses uses.

#### KIT 11. Smaller TesserKIT bugs

All low unless noted.

- **Disabling Art-Net or sACN can deadlock the device task** (medium-low, reasoned) if an application's `DmxSink` takes the API lock: `tick()` holds the lock while `socket_.reset()` waits for the receiving task (`dmx.cpp:176-178`, `udp_esp.cpp:29-34`). Either state "never take the API lock" in `DmxSink`'s contract, or stop the socket outside the lock.
- **The NowTP pairing task races with disabling or forgetting** (reasoned): `nowtp.cpp:137-143, 358-364`. `pair()` blocks up to 60 s on `radio_` while `end()` runs and clears `pairingBusy_`. Refuse both while pairing.
- **`Device::loop` copies `hostname_` without the API lock** (reasoned): `device.cpp:376-380`.
- **`coredumpPresent` stays true after `clearCoredump`** (confirmed): `system.cpp:140-144` doesn't call `changed()`.
- **A late ScanDone leaves ESP-IDF's AP list allocated** until the next scan (confirmed): `network.cpp:861, 1210`.
- **`ipConfig()` logs "no static address" every second** while the DNS list is empty (confirmed): `network.cpp:75-83, 565, 960`.
- **`Device::begin()` after a failed `startServer()`** leaves `started_` true, so a retry returns true without a server (`device.cpp:325-334`).

### TesserUI

#### UI 1. Peer root schemas are fetched an exponential number of times

High, confirmed by simulation (`tesserui-copy/web/test/zz_peers.test.ts`: 6 peers → 63 requests). `web/src/store/session.svelte.ts:826-829`, `web/src/Page.svelte:42-44`.

- **What happens:**
  - Every `show()` starts a sequential loop over the peer links without a tree. Each reply calls `merge()`, which bumps `schemaVersion` and re-runs Page's effect, so another loop starts over the remaining peers.
  - Nothing deduplicates requests in flight, and the localStorage cache is checked before any reply arrives.
  - On a gateway this exceeds `maxPending` = 4 at once: the gateway answers `busy`, `ask()` retries each request 4 times, and error toasts follow.
- **Fix:**
  - A `Map<key, Promise<boolean>>` of fetches in flight in `fetchSchema`. This also covers the concurrent `ensure()` calls.
  - Ask each peer once per hash in `show()`.
  - Add a test.

#### UI 2. A subscribe that times out leaves subscriptions on the node

Medium-high, confirmed on both sides. `web/src/store/subs.ts:85, 208, 262-264, 284-286`; TesserAPI `api.cpp:1051-1076`.

- **What happens:**
  - A timed-out `sub` is marked failed and retried every 5 s, but the node may have accepted it. TesserAPI adds a new subscription for each `sub`, even at the same path.
  - `want()` and `sleep()` skip the unsub for failed entries.
  - Orphans count against `maxSubscriptionsPerClient` (4): pages fall back to polling and the events subscription is refused.
- **When:** serial and BLE (damaged lines), relayed subscribes, loaded nodes.
- **Fix:**
  - `unsub` before retrying after a timeout.
  - Unsub entries that failed by timeout on leave.
  - Optionally, TesserAPI replaces a subscription at the same path for the same client.

#### UI 3. A dead WebSocket is never noticed

Medium-high. The missing check is confirmed; the browser behaviour is reasoned. `web/src/client/envelope.ts:90-101, 138-169`.

- **What happens:**
  - TesserAPI sends no WebSocket pings, and a subscribed page sends nothing.
  - A node that loses power without a FIN leaves the socket "open", and the page shows "Live" with frozen values until the user writes something.
- **Fix:**
  - After 20–30 s of silence, send `get / view=info`.
  - After two timeouts, close the socket (the existing reconnect takes over) and mark specs stale.
  - Optionally, WebSocket pings from TesserAPI would also free dead clients' subscriptions on the device.

#### UI 4. Over HTTP, one slow request takes the whole session "down"

Medium, confirmed by trace. `web/src/client/http.ts:126-131`.

- **What happens:**
  - Any failed or timed-out fetch calls `setState('down')`: every control is disabled and the banner shows.
  - The next success runs `resume()`, which re-reads every spec at once on a node that was already slow.
  - The WebSocket client doesn't behave this way.
- **Fix:** go down only on network errors or repeated probe failures, and treat a timeout as `timeout`.

#### UI 5. Smaller TesserUI bugs

- **A closed session comes back to life** (medium-low, confirmed by trace):
  - **Where:** `session.svelte.ts:264-290`.
  - **What happens:** a session that fell back to HTTP probes for a WebSocket every 5–60 s. `close()` doesn't stop the probe, so a launcher tab's closed node reopens a WebSocket forever, holding one of the device's few sockets.
  - **Fix:** a `closed` flag checked by `probe` and `start`; clear the `stubRefresh` timers too.
- **Lazy widget chunks return 404 after an update with the same schema hash, permanently** (medium, confirmed by trace):
  - **Where:** `widgets/registry.svelte.ts:40-56`, `src/tesserui/web_ui.cpp:145-161`.
  - **What happens:** a release that bumps only TesserUI keeps the open tab's old `ui.js`. Its chunk names no longer exist, and `lazy()` stays `loading` forever.
  - **Fix:** on an import failure, reload once (guarded by sessionStorage), or compare the bundle's ETag after reconnecting.
- **Hold buttons repeat without waiting, and the release isn't retried** (medium, reasoned; safety-adjacent):
  - **Where:** `widgets/Action.svelte:75-82`, `lvgl_ui.cpp:2128-2136`.
  - **What happens:** through a gateway, repeats pile past `maxPending`. The release `false` can then be refused `pending_limit` and isn't retried, so a motor stops only at the device's dead-man timeout.
  - **Fix:** skip a repeat while one is in flight, and send the release through `ask()` (which retries).
- **The schema cache in localStorage is never evicted** (medium; no eviction is confirmed, the quota effect reasoned):
  - **Where:** `session.svelte.ts:744, 770`.
  - **What happens:** the key includes the hash, so every update and every gateway hash change adds entries. At the quota, `setToken()` silently fails, which gives a sign-in loop.
  - **Fix:** key by node and path with the hash in the value, and store tokens first.
- **The events subscription receives every log line** (medium, confirmed by code):
  - **Where:** `subs.ts:28`, TesserKIT `log.cpp:77, 131`.
  - **What happens:** every admin tab gets every event of the tree, and the device serialises each one per subscriber.
  - **Fix:** a TesserAPI `sub` option keeping only events with a hint (`events: "toast"`).
- **Polled specs stay polled after the WebSocket returns** (low-medium, confirmed by trace): `renew()` keeps the poll mode. Upgrade poll entries when the client subscribes again.
- **Every button press costs two `view=info` reads,** and a 2.5 s stall forces a reconnect (low, confirmed):
  - **Where:** `Action.svelte:45`, `session.svelte.ts:393-407`.
  - **Fix:** watch only restart actions.
- **A stalled download loops forever** (low, reasoned):
  - **Where:** `client/files.ts:75-84`.
  - **What happens:** a non-final empty chunk leaves `offset` unchanged.
  - **Fix:** a stall guard like `upload()`'s.
- **HTTP downloads decode the whole blob as text for nothing** (low, reasoned): `widgets/transfer.ts:29`. Read the text only on an error status.
- **A page that fails to load keeps the previous page's subscriptions** (low, confirmed by trace): `Page.svelte:42-44`.
- **LvglUi's destructor leaves `menuTimer_` alive,** and `loadChoices`' inner callback captures `this` without `alive` (low, confirmed by reading): `lvgl_ui.cpp:283-299, 884, 1267, 3125`.

### RAM 1. Per-node metadata: about 20–22 KB in `/sys`

High value, confirmed: sizes measured on xtensa, counts from `fixtures/sys.json`. Two reviewers found this independently. TesserAPI `src/tesser/node.h:38-75`, `node.cpp` (`editMeta`, `editUi`, `addHint`).

|---|---|---|

**What `/sys` holds:**
- 281 resident nodes, 256 with `NodeMeta`, 251 with `UiMeta`, 283 hints: about 22 KB at rest, twice the nodes.

- DESIGN §11's "RAM at rest ≤ 12 KB" can't be holding.

**Fix, in TesserAPI:**
- One slim metadata allocation of about 24 B: access, doc, label, unit, a float step, a hints pointer, and flag hints as bits.
- Range doubles, validator and watch hash in a rare `Extra*`.
- Hints as one array per node, or static `constexpr` tables an app passes and that stay in flash.

**Saving:** 9 KB with the slim struct, 12–15 KB with packed or flash tables. **Measure first:** compare the free heap before and after `begin()`'s attach, and correct DESIGN §7.1 ("16 bytes, plus 16 per hint") and §15 (36 B).

### RAM at rest

- **Bluetooth's reservation.** The controller reserves 56,156 B of DRAM at link time. NimBLE gives back the BR/EDR part (15.4 KB) when it starts, so about 40.7 KB stays in use while Bluetooth runs.

  - **Fix:** call `esp_bt_mem_release(ESP_BT_MODE_BTDM)` in that case (`ble_esp.cpp`/`bluetooth.cpp`); switching Bluetooth on then needs a restart. DESIGN §5.10 needs the note.
  - This makes the full profile's Bluetooth an opt-in that costs nothing when off.
- **NimBLE's pools** take about 22 KB while Bluetooth runs. `MSYS_2_BLOCK_COUNT` and `TRANSPORT_ACL_FROM_LL_COUNT` from 24 to 12 would save about 7 KB; check long notification streams over BLE.

## Efficiency

- **Route resolution allocates on every tick and notification** (TesserAPI, confirmed: `mesh/repro/allocs.cpp`).
  - **Where:** `remote_routes.cpp:131-159`, `remote.cpp:357-407, 523-525`, `datagram_peers.cpp:298-305`.
  - **Measured:** with 16 remote nodes and a route order set (as TesserKIT sets it), 58 allocations per idle 20 ms tick, about 2,900 a second.
  - **Lock violation:** `orderLocked()` takes two more locks under the routes lock, which is documented as a leaf.
  - **Fix:**
    - Cache the effective order under a generation counter.
    - Return early from `tick()` on endpoints that aren't the active route.
    - Reuse scratch vectors for pins.
    - Let the UDP worker sleep until its next deadline, which also matters for Sleep devices.
- **UDP sends retry ENOMEM by sleeping under the link lock, and often the API lock** (TesserAPI, reasoned).
  - **Where:** `udp_transport.cpp:177-190`.
  - **What happens:** up to 20 × `vTaskDelay(1)` per datagram. It also blocks the receive task inside `packet()`, so lwIP's 6-entry mailbox overflows and acks are lost.
  - **Fix:** leave refused reliable fragments to the 100 ms retransmission timer, and defer acks and broadcasts to `tick()`.
- **The NowTP task wakes 200 times a second when idle** (confirmed by reading).
  - **Where:** `espnow_transport.cpp:680-688`.
  - **Fix:** sleep `pollDelayMs()`, and have `unlock(changed)` notify the task. TesserKIT polls, so this affects other apps only.
- **`Network::updateStatus` allocates strings every 20 ms** (TesserKIT, confirmed).
  - **Where:** `network.cpp:1241-1277`.
  - **What happens:** many state strings exceed 15 characters, e.g. "not needed: Ethernet has a DHCP address" on every Ethernet board, or "no network saved". That is 50 malloc/free pairs a second.
  - **Fix:** `const char*` for fixed states; build dynamic ones only when their inputs change.
- **Every file change walks the whole LittleFS and re-lists the backups under the API lock** (TesserKIT, confirmed).
  - **Where:** `files.cpp:411-421, 575-580`, `stored_backups.cpp:120-132`.
  - **Fix:** rate-limit `refresh()` to about once every 2 s, and list `/backups` only when it changed.
- **Keyed-list resolution builds every element and a `JsonDocument` per key** (TesserAPI, confirmed).
  - **Where:** `api.cpp:468, 1238`, `ListNode::keys`.
  - **Fix:** compare against the key's quoted form and stop at the first match.
- **`uploadFilter()` builds a `JsonDocument` for every upload chunk** (TesserAPI, confirmed).

## Maintainability

- **TesserAPI `api.cpp` (1,716 lines)** is one Handler of about 1,200 lines that mixes resolution, rendering, patches, subscriptions and fan-out.
  - Split it into resolve, render and patch.
  - **Path walking** is written four times with different rules: `Handler::resolve` rejects empty segments, while `belowRemote`, `Api::changed` and `readNeed` skip them. One walker.
  - **Query options** are parsed twice and listed in three places that must agree: `checkStrict`, the FileSession keys (twice) and `uploadFilter`. Make them one table.
  - **Request, auth and file dispatch** is duplicated across `LineTransport::handleLine`, `handleEnvelope` and `DatagramEndpoint`; **token re-checks** across `WsClient`, `LineTransport` and `StreamSubscriber`.
- **TesserAPI `http_server.cpp` (1,557 lines)** mixes parsing, WebSocket, streams, async replies, files, mDNS and strict mode.
- **TesserAPI's mesh side:**

Give the parts a narrow `RemoteContext` (api, localPath, remotePathOf, route, online, timeoutMs, changed, request), drop the friend, and move `RemoteHooks` to its own file. This combines with RAM 2's lazy parts.
  - **DatagramEndpoint** (652-line header, about 32 KB of code) is now the larger god-object. Its three .cpp files become classes sharing the endpoint's one mutex:

## Overall

Each reviewer found its part carefully written for its constraints:
- millisecond wraps are handled almost everywhere (one exception, NowTP 2);
- allocation failures are mostly reserved and refused rather than aborted;
- the lock ranks hold;
- the specs are detailed and mostly accurate.

The problems cluster in four places:

1. **Lifetimes across a released lock or a teardown:** T-API 1, 5, 6, 7, 8; KIT 11's pairing and DMX cases; UI 5's closed session. Each is a rare path that ends in a use-after-free, a deadlock or a leaked slot.
2. **Paths that still bypass the byte budget** (RAM 3), and per-second rebuilds that churn the heap. These are exactly the abort paths Phase 1 set out to close.
3. **State copied between modules and falling out of step:** NowTP's frame sizes (NowTP 1), Mqtt's hostname (KIT 7), the UDP id spaces (T-API 2), the settings' two homes (KIT 1).
4. **Memory at rest that's structural, not per feature:**
   - per-node metadata (RAM 1) and RemoteNode (RAM 2), about 30 KB on a gateway with 16 peers;
   - Bluetooth's reservation when it's off (56 KB);
   - oversized task stacks (10–15 KB).

   All of these shrink without removing any feature, which fits Leo's rule: keep features, save space where it costs no performance, clarity or ease of use. The configuration changes trade a little capability for flash and are his call.
